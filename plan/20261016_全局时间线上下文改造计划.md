# 全局时间线上下文改造计划（2026-10-16）

> 本计划取代 [`20261016_全局作息状态机与睡眠期记忆整理计划.md`](20261016_全局作息状态机与睡眠期记忆整理计划.md)
> 里「注入四段式」的第三段与 `merge_missing_into_contexts` 的合并机制。
>
> **后续变更（v1.3.0）**：[记忆分层压缩与位置榜计划](20261016_记忆分层压缩与位置榜计划.md)
> 又推翻了本计划的几处：上下文除账本外还包含**活着的摘要**（`condensed_at = 0`）；
> `_rebuild_native_history()` 与 `schedule.rebuild_native_history` 已退役；注入块的
> 「长期记忆」段改为「永久记忆 + 榜前 10 条正文 + 其后 30 条关键词索引」。

## 1. 起因

用户提问：「当我问模型最近是否有人与他聊天时，模型的第一反应是去『看看』，
这是否证明与我聊天时上下文并不是自然衔接着别人的会话？」

取证（真实库副本上跑出注入块原文）：

- 旧机制确实把别人的会话塞进了请求——30 行、2460 字符、覆盖 6 个会话。
  **数据不缺**。
- 但它是一条 `role: "user"` 的消息，被 `req.contexts = prefix + req.contexts`
  放在**所有内容最前面**，还带着四条禁令（不要复述 / 不要说来源 / 不要用
  旁观者口吻 / 只在自然相关时才带出来）。
- 角色被压平：她在别处说过的话也是一行文本，不是 `assistant` 回合。
- `list_sessions` / `peek_session` 的 docstring 正好在邀请它「去看看」。

结论：模型「去查」是对这种呈现方式的合理反应。它读到的是**一份别人写给它的
简报**，不是自己的记忆。

## 2. 目标形态

**单一全局时间线**——所有会话按时间排进同一条脉络，作为主脑**唯一**的上下文。

```
[群聊·592701974] XvX：上下屏一般得专门的支架
我：这个得看支架高度，普通的不够
[私聊·白纸·3470401767] 白纸 (23小时前): 爱丽丝晚安哦
我：晚安白纸，快去睡吧
（你现在在「私聊·白纸·3470401767」说话。……）
```

- 她说过的话 = `assistant` 回合，只放原话，不带前缀。
- 别人的话 = `user` 回合，正文自带 `[会话标签] 发言人 (多久前):`。
- 末尾一行标明她此刻在跟谁说话。
- **切会话不换上下文**，只有最后那条消息换了个人。她只在主动 `say` 时换对象。

## 3. 用户确认的口径

| 决策点 | 结论 |
| --- | --- |
| 改造范围 | **直接全量替换** `req.contexts`，不加开关 |
| 时间线跨度 | **只保留今天**（本轮清醒周期） |
| 短期记忆语义 | 起床后重新累积；前几天的内容靠深睡整理进长期记忆；睡觉时没人发消息则刚起床时短期记忆为空 |

「只保留今天」不需要新机制：时间线取 `archived_at = 0 AND staged = 0` 的账本行，
深睡整理归档后自然清空；睡眠期消息在叫醒/起床 `release_staged()` 后才进来。

## 4. 前置风险验证

原担心「整体替换 contexts 会截断工具调用链」。查证 AstrBot 源码后排除：

- `on_llm_request`（插件钩子）在 `astr_main_agent.py` 的 `_decorate_llm_request()`
  之后、`agent_runner.reset(request=req)` **之前**只触发一次
  （`agent_sub_stages/internal.py:307`）。
- 工具多轮往返发生在 `AgentRunner` 内部，不再经过插件钩子。

因此整体替换是安全的。官方文档（`docs/advanced_request_building_guide.md`）
本身也推荐 `req.contexts = 自己重建的历史`。

## 5. 实现

| 文件 | 改动 |
| --- | --- |
| `core/memory/timeline.py` | **新增**。`build_timeline(rows, current_prompt, token_budget)`：按时间正序渲染，`assistant` 取干净正文，`user` 复用 `format_message_line`，剔除当前消息（按 content 精确匹配最后一条 user 行），超预算**从最旧的**开始丢，末尾补「你现在在跟谁说话」。每条带 `_no_save`（时间线是每轮重建的视图，不能固化进官方历史）。 |
| `core/memory/ledger.py` | 抽出 `format_speech()`（`format_message_line` 复用它）；新增 `timeline_rows(limit)`（`archived_at = 0 AND staged = 0`，时间正序）。`_context_rows` 简化为「整个排除正在判定的会话」，去掉已无意义的 `gated/backfill` 特例。 |
| `main.py` | 新增 `_rebuild_timeline()`：把 `req.contexts` 整体换成时间线（失败则保留原生上下文并告警）。`_inject_memory_blocks()` 改为「时间线替换 + 记忆块前置」。删掉 `_merge_missing_messages()`。 |
| `core/common/config.py` + `_conf_schema.json` | 新增 `memory.timeline_max_messages`（400）/ `timeline_token_budget`（8000）；删除 `memory.merge_gated_into_contexts`（已无意义）。 |
| `core/memory/history.py` | 删除 `merge_missing_into_contexts()`；保留回填与坏图清理。 |
| `core/memory/injector.py` | 删除 `build_recent_context_block()` 与 `_RECENT_HEADER`。 |

## 6. 影响

**简化掉的**：`build_recent_block` 不再参与主脑上下文（只留给决断层判定）；
补回合、跨会话语境块、`merge_gated_into_contexts` 开关全部退场；历史图片 part
不再进 contexts（时间线用 `[图片]（图片内容：…）`），坏图风险随之下降。

**`gated` 降级为展示用**：上下文由时间线整体重建，「那轮主脑看没看到」不再需要
靠标记补回。字段与写入保留（记忆页面、排障仍有价值），但**不再参与上下文组装**。

**仍然保留 `_rebuild_native_history()`**：官方历史对我们已无用，但别的插件
（如天使之心）可能仍在读写，不去动它。

## 7. 验证

容器内冒烟测试（真实库副本 + 合成数据，26 项全绿）：

- 配置与 schema 一致，`merge_gated_into_contexts` 已移除。
- 合成数据：时间正序、`assistant` 回合无前缀、`user` 回合带会话与发言人、
  当前消息不进时间线、末尾标记指向当前会话、全部 `_no_save`。
- 预算：从最旧的开始丢，再紧也至少留最新一条 + 标记。
- 真实库（856 条账本）：取到上限 400 行、SQL 时间正序、不含归档/暂存行；
  渲染 188 条 / 16107 字符（约 8000 token，正好触到预算），162 条他人消息带
  括号标签，assistant 回合全部干净，当前消息未重复。
- `compileall` 与 `import astrbot_plugin_shittim.main` 通过。
