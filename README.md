# AstrBot Plugin Shittim · 什亭之枢

> 让驻留在什亭之匣中的智能体，在 QQ 中自由活动。

`astrbot_plugin_shittim` 让一个拥有统一人格与完整上下文的智能体，能够自主决定**对谁说、在哪个会话说、什么时候说**。它不是等着被 @ 的应答机：会按自己的性格和记忆判断该不该接话，能跨会话走动，也会在确实无话可说时安静待着。

---

## 设计理念

### 思考与发送分离

传统插件是「收到消息 → 生成回复 → 发回原会话」。什亭之枢把这条链路拆开：

- **决断层**：先判断这条消息值不值得回应，不值得就让官方 LLM 完全不触发（`stop_event`）。
- **主脑**：只在决定要回应时才生成回复，负责「怎么说」。
- **行动层**：由插件负责把话准确投递到任意私聊或群聊，并维护她「现在在哪」。

### 像人一样挑时机

人不会对每一句话都做一次判断。听到一句话先等对方把这段说完，再决定要不要接；判断不接就安静一阵。

插件也是这么做的：群聊里的普通消息先在**巡检窗口**里攒几秒，攒够了再整体判一次。这既省下大量模型调用，也让判定有完整语境——单看一句「应该可以」，模型根本不知道在说什么。

判定时她看到的是：**自己的人格、永久记忆、按话题召回的相关记忆、其它会话刚发生的事，以及这段对话之前紧邻的几句**。判断的不是「有没有人叫我」，而是「这段话是不是在叫我、有没有非接不可的理由」——拿不准就不开口。

### 统一灵魂，全域记忆

无论谁在私聊她、在哪个群聊和她说话，她始终是同一个人。

所有会话的消息进同一本**短期账本**，长期记忆与永久记忆跨会话共享。默认情况下她沿用 AstrBot 原生的按会话历史，同时把**其它会话最近发生的事**作为临时内容块带进本轮请求——所以**切会话不换认知**，只是换了个说话对象；这些临时内容只作用于当轮，不写入持久历史，也不会破坏原生前缀缓存。

若希望她完全以同一条全局时间线思考，可开启 `memory.context_takeover`：插件会用账本重建的全局时间线整体替换请求上下文。

## 核心特性

- **接管官方 LLM**：所有消息先记账，再由规则层与巡检窗口决定是否放行主脑。要回应就置位唤醒标志放行，不回应就拦下，官方 LLM 完全不被触发。
- **按人格与记忆接话**：判定层会读入当前人格提示词、永久记忆与按话题召回的长期记忆，再结合窗口前文判断「这段话是不是在叫她、有没有非接不可的理由」。默认不开口，只有明确的接话点才开口；纯刷屏、复读、表情和别人的私事都不会让她出声。
- **群聊巡检**：不逐条判定。收到群消息后等 10 秒，期间每来一条新消息就重新计时，直到没人说话才整体判一次；判为不回则该会话停止检测 60 秒，之后继续等待新消息。
- **静默防抖**：私聊与群内 @ 一定要回，但先等对方说完——最后一条之后安静满 10 秒才开口。文本里只是提到名字时，则交给判定模型确认是不是真的在叫她。
- **判定理由只当自己的念头**：判定层放行时会说明「为什么值得接」，这句话以她**自己刚冒出的想法**出现在上下文末尾，既让两边对同一条消息的判断一致，又不会变成一段需要回应的对话。
- **主脑可主动沉默**：`stay_silent` 让主脑在判定失误、念头站不住、或认为这话不该接时，直接丢弃本轮发言。
- **噪声不进模型**：整段只有图片/表情、整段复读、同一人连刷短句，直接拦下——既省调用，也不让她因此沉默一分钟。
- **跨会话穿梭**：`list_sessions` 看有哪些地方可去，`peek_session` 隔窗看一眼，`enter_session` 走过去看看那边她不在时发生了什么，`say` 在那里说话，`leave_session` 离开，`rest` 全体静默。进过会话或说过话之后，那边之后的消息才算「新收到」。
- **翻旧账**：`peek_session` 只看当下，`search_history` 按关键词翻聊天记录——已经清空、已经压进摘要的那些也能找回来。她不需要把一切都记在脑子里，只要记得去哪儿翻。
- **推迟入睡**：`delay_sleep` 让今晚晚点睡，入睡与起床一起顺延（受起床上限约束），只对当次有效，明天照常。
- **说在那边，不在这边**：她去别的会所说的话不会被搬回原会话复述一遍；只是走进去、还没开口时，本轮想说的那句话会直接说在那里，不会凭空消失。
- **三层记忆**：
  - *短期账本*：跨会话原始消息，带来源与时间标记，防止把 A 群的话回到 B 群。条目超阈值时自动把最旧的一批压成摘要，别让上下文无限变长。
  - *长期记忆*：由独立的轻量模型在压缩时顺带产出，排在一条**位置榜**上。新提炼的记忆按它覆盖的对话时间落位，当天摘要与被重新提到的记忆落在当下；每次被主动想起都会上浮到前，用得少的自然沉下去、逐级变模糊、最终被遗忘。
  - *永久记忆*：被反复用到或被她明确要求记住的，不排榜、不降级、不遗忘。
  - *无价值记忆的两段式遗忘*：整理时如果某条记忆的正文、原话、关键词都只剩「事实 / 结论」这类分类词，读不出任何具体的人、事、物，就先标成「待遗忘」；下一次整理才真正删除。中间这一轮里只要它被想起、又被提到或被手工编辑过，标记立即解除。页面上的「待遗忘」标签就是它。
- **用户画像**：以 QQ 号识别同一个人，私聊与各个群聊共用一份印象——同一个人在群里和私聊里换了昵称，也还是同一个人。名字随发言实时累积，所以她能认出「小绿」和「绿」是同一个人；整理时既看最近的发言，也看已经沉淀成**长期 / 永久记忆**的事实，所以被压缩掉的旧认知不会丢。有些记忆整条就是「关于这个人的事」，被画像完整吸收后会直接删除，避免同一件事记三遍（明确要求记住的不在此列）。当前说话人的画像会作为背景注入，让她「认识」眼前这个人；页面可逐人查看。
- **工具清单常驻**：所有工具连同「什么时候用、和哪个兄弟工具怎么分工」以一段稳定文本每轮注入，模型不必只靠函数声明猜用法；它讲的是能力，不掺任何性格或说话方式。
- **记忆注入按读取顺序**：工具清单 → 当前说话人的画像 → 与当前消息相关的少量召回（默认 3 条）→ 永久记忆 → 榜前 10 条正文 → 其后 30 条模糊索引（每条只给开头一截，提示她「还忘了什么」，需要时自己 `recall`）→ 跨会话背景（其它会话的消息与摘要，以及当前会话里没进官方历史的被拦消息）→ 当前消息 → 判定念头 → 位置提示 → 作息事件提示。这些内容以临时块追加，不修改原生上下文。自动召回不计入「被想起」，只有她主动 `recall` 才会移动榜序。
- **图片转文字**：AstrBot 给图片的只有「[图片]」占位，插件自己问一次视觉模型，把描述写回账本，于是判定、语境、页面都能「看见」那张图。
- **合并转发转文字**：QQ 的合并转发只带一个消息 id，AstrBot 也只能给出「[转发消息]」占位；插件会把里面的聊天记录取回来写进账本，她同样能读懂转发了什么。
- **记忆页面**：WebUI 插件页里查看短期账本（含摘要块）与各层记忆，含图片描述、转发内容、榜上名次与档位、标签、最近想起的时刻，以及当前作息（阶段 / 入睡与起床时刻 / 上次整理）。长期与永久记忆可以直接**手工编辑正文或删除**（删除后不会被下一次压缩重新写回）；用户画像也能**编辑描述与关键词或整份删除**，删除只清印象，名字与发言记录保留，他下次说话会重新建行。
- **巡检与焦点面板**：同一页面里对照查看巡检参数（窗口时长、判为不回后的冷却、防抖、噪声过滤）与此刻的真实状态——正在计时的窗口、正在判定的会话、冷却剩余时间、每个会话最近一次判定（开口 / 沉默 / 冷却拦下 / 未判定及理由），以及焦点的关注中、已离开、已超时。消息「为什么没被放行」在这里一眼可查。
- **当前上下文查看**：按会话查看主脑最近一次请求**真正发出去的内容**——系统提示词、上下文条目（原生历史或账本时间线）、本轮用户消息、以及追加在末尾的临时块（工具清单、用户画像、记忆、跨会话背景、判定念头、位置提示、作息提示）。排障时不必再靠猜「记忆到底注入没有」。
- **风控**：目标白名单 + 每分钟/每小时限流。

## 架构概览

### 五条链路

**拦放链路（接管官方 LLM）**

```
所有消息 → 记入短期账本 + 刷新该会话焦点 → 决断层规则层
  ├─ 上游指令 / 被点名 / 无文本 → 当场定夺
  ├─ 私聊 → 要回，但先进静默窗口：安静满 10 秒才放行主脑
  └─ 群聊里的普通消息 → 巡检窗口：攒一小段对话再判一次
       · 判据 = 人格 + 永久记忆 + 相关召回 + 其它会话近况 + 本会话前文 + 窗口内容
       ├─ 不回 → stop_event()，官方 LLM 完全不触发，该会话安静一阵
       └─ 要回 → 置位唤醒标志，放行主脑生成回复
```

**焦点链路（她在哪）**

她可以同时在多个会话里「在场」，像一个人同时开着几个聊天窗口。收到某会话的消息 → 该会话获得焦点；安静超过 N 分钟 → 焦点失效（她休息了）。焦点**只约束主动发言**：被动接话永远不受限，任何消息都能唤醒她。

**记忆链路**

短期账本 → 条目**超阈值就压一轮**（按条数触发，不按时间；同一次调用产出「1 条摘要 + N 条长期记忆」）→ 长期记忆排在**位置榜**上 → 降级/遗忘/晋升/合并。新提炼的记忆按它覆盖的对话时间入榜，只有当天摘要与被重新提到的记忆落在当下，避免每晚整理把榜单整版刷新。主脑每轮还会按当前消息额外召回少量相关记忆（不改变榜序）。用户画像按 QQ 号跨会话累积，整理时用这个人最近的发言重写描述与关键词。图片消息额外走一次视觉转述、合并转发额外取回一次聊天记录，结果都回填账本。

主脑默认沿用 AstrBot 原生的按会话历史，并在其后追加说话人画像、话题相关召回、长期记忆、跨会话近况与作息提示这些**临时内容块**——切会话不换认知，只换说话对象。开启 `memory.context_takeover` 后改由账本重建的**全局时间线**整体替换上下文。深睡整理把当天账本收口清空后，上下文从零重新累积——前几天的事由长期记忆承载（当天的经历先被压成一条**当天摘要**写进榜最前）。

**作息链路与深睡整理**

清醒 / 浅睡 / 深睡三态，睡眠期只放行命令、被叫醒后进入清醒宽限。深睡期每晚整理一次：降级 → 遗忘 → 晋升 → 合并 → **短期收口**（树状压成一条当天摘要并写进榜最前）→ 清空当天账本 → 按保留期清理。收口与清空只在深睡期做，清醒期的兜底整理只跑维护——否则等于当场失忆。长期记忆按**榜上名次**逐级变模糊（榜前 60% 完整、到 85% 精简、之后只剩关键词），每次被召回就上浮回榜前；沉到榜尾再叠加「降级次数 + 连续未召回」才遗忘。`forget` 工具可以让某件事被明确忘掉且不再被重新记住。

**行动链路（跨会话穿梭）**

`list_sessions` 看有哪些会话 → `peek_session` 隔窗看一眼（不改变她在哪）→ `enter_session` 走过去看未读 → `say` 在那里说一句 → `leave_session` / `rest` 离开。

走进会话与直接发言的区别：`enter_session` 只切换位置，把她离开期间那边攒下的消息作为「看到的」交给她，不算刚收到的新消息；`say` 是直接开口。只走进去、还没说话的那一轮，她想说的那句话会直接说在那个会话里（`redirect_reply_to_target` 可关）；已经说过话的收尾不会重复发。

## 使用示例

### 私聊让她去群里说一声

> **你（私聊）**：爱丽丝，去群里说一声，优香下午要来活动室查社团预算，先把桌上的卡带和零食收一收。
> **她**：好，我这就去。
> *（她调用 `list_sessions` 找到群、`say` 过去说了话，然后留在那边；不会跑回来汇报）*

### 群里让她私聊某个人

> **你（群聊）**：爱丽丝，私聊催一下小绿，新作的立绘今晚之前得交；顺便问凯伊预算表整理好没有。
> **她**：收到。
> *（她分别调用 `say`，目标 session 填小绿和凯伊的 QQ 号）*

### 她主动记住一件事

> **你**：柚子怕生，群里别突然点她名字，有事私聊。
> **她**：*（调用 `remember` 工具，这条记忆晋升为永久，不会衰减）*

## 配置

配置项在 AstrBot WebUI 的插件配置页，按功能分组：

- **memory**：记忆开关、压缩模型、**压缩阈值与批大小**、**是否接管主脑上下文**（默认关闭；开启后用全局时间线替换原生上下文，可配 token 预算与条数上限）、跨会话语境的配额（供决断层、巡检与主脑的跨会话连续性块使用）、榜前正文与关键词索引的条数、**主脑自动相关召回**（条数与独立预算）、**永久记忆的独立预算**、**用户画像**（开关、是否注入、单次整理更新的用户数 / 时间窗口 / 最少新发言数）、图片转文字（是否启用、用哪个视觉模型、单条最多转述几张）、合并转发（是否启用、单条最多读取几条 / 多少字）、位置榜的遗忘门槛与晋升条件。
- **decision**：是否接管对话、决策模型（判定时会自动读取当前人格与记忆，无需单独配置）、私聊是否直接放行、@ 是否必回、文本提到名字是否交给模型确认、唤醒词、判定时每个会话带入的近期消息条数（也用于补窗口前文）、**私聊与 @ 的防抖时长与最长等待**，以及**群聊巡检**参数（静默窗口时长、判为不回后的冷却、噪声预过滤）——**开口之后不设冷却**，她说完一句，下一条消息立刻重新进入判定，连续对话不会断。
- **focus**：会话安静多久收回主动发言资格、主动发言前是否必须持有焦点。
- **schedule**：入睡与起床时间、起床上限、深睡阈值、叫醒信号门槛与清醒宽限、每日整理开关与兜底间隔、账本清理开关与归档保留天数。
- **proactive**：是否允许主动发言、目标白名单、每分钟/每小时限流、离开后是否还回原会话收尾。

## 安装

1. 在 AstrBot WebUI 的插件市场搜索安装，或把本目录放进 `data/plugins/`。
2. 重启或重载插件。
3. 至少配置一个**轻量决策模型**（`decision.provider_id`，留空则复用记忆压缩模型）。想让她看得见图片，还需要一个支持图片输入的**视觉模型**（填 `memory.vision_provider_id`，或直接配好 AstrBot 全局的「图片转述模型」）。
4. 插件详情里会多出一个「什亭之枢」页面，用于查看记忆、用户画像、巡检与焦点状态，以及主脑当前上下文。
